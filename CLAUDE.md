# DriftLobby

DriftLobby is a private, play-credit arcade for friends. Keep the dark lobby, all 14 games, editable wagers, Blackjack table, sound settings, wallet, and profit tracker. Chicken Cross and Moles were intentionally retired. Credits have no cash value and cannot be purchased or redeemed.

## Scripts and anti-cheat
dist/index.html loads only dist/boot.js (plus the two config files). boot.js reads the game scripts as text and runs them inside one private scope, so nothing is reachable from the console; from file:// it falls back to ordinary script tags. After changing any script, raise VERSION in boot.js so browsers fetch the new copy, and add new script files to its list (a test checks this). No game may save an answer before it is played: Mines, Tower and Blackjack decide each tile, door and card at the moment it is revealed. Saves carry a `seal` checksum (app.js); a save edited outside the game is reset to fresh profiles. These deter tampering but cannot stop someone who edits the code itself, because everything runs in the player's browser.

## House advantage
Tower, Mines, Limbo, Dice, Hi-Lo, Coinflip, Rock Paper Scissors, Wheel, and War pay every win in full (2x coinflip, the fair multiple on Tower, and so on). The house's advantage is in how often a win happens, and it grows with the bet: `share(bet)` in dist/engine.js is the part of the normal win chance the player keeps. From 1 to 200 credits it slides from 100% to about 93%; over 200 it is 60% (an even-money bet wins 30%, the house 70%); over 1,500 it is 0 and the bet cannot win. `houseTakes(bet)` decides whether the house takes a round the player would have won, and the round helpers beside it (`coinFace`, `diceRoll`, `limboRound`, `warDraw`, `houseThrow`, `wheelStop`, `safePick`) turn that into a losing result. In Tower, Mines and Hi-Lo the bet size counts on the first pick only. The owner asked for these figures; the condition for building them was that they are not hidden. The chance for the bet entered is shown under the bet amount (`oddsNote`, `showOdds` in dist/tables.js), in each table's rules (`sizedRule`), and on the Fair Play page (dist/legal.js), so change all of them when a figure changes. Roulette, Plinko, Keno, Baccarat, and Blackjack keep their own standard rules and ignore the bet size; player flips are fair and take no fee. tests/wagers.test.cjs and tests/balance.test.cjs check the payouts and the win rates.

## Run
From this folder run `python3 -m http.server 8000 --bind 127.0.0.1 --directory dist` and open http://127.0.0.1:8000. The editable HTML, CSS, browser JavaScript, and artwork are in dist/. No frontend build step is required.

## Settings and policies
Settings (account.js) covers sound, gameplay, chat, privacy, profile, and data-reset options; site settings are saved under `driftlobby.settings.v1`. The policy pages (Terms, Privacy, Refunds, Fair Play, Community Rules, Play Responsibly, Storage) are in dist/legal.js and must stay true to what the site does: free credits, nothing for sale, saves in the browser, simulated chatter disclosed. Chat supports @mentions with a highlight for the person named.

## Accounts
The top-right profile button opens an account menu (Connect Discord, or Switch account and Sign out). There is no pass-and-play player switcher. Each Discord account is tied to its own saved profile through `discordId` on the player record; signed-out play uses an unlinked guest profile. Profiles still live only in this browser's saved data, not on a server.

## Profit tracker
The profit tracker is a draggable "Live stats" panel inside the page (dist/live-stats.js, styles in dist/profit.css), not a pop-up window. It shows wagered, profit, a profit chart, wins, and losses since the player last pressed reset. The tally is kept per player as `live` in the saved profile and is updated in `record()`; the all-time `profit.net` is separate and never reset.

## Chat
The left chat panel (dist/chat.js, dist/chat.css) signs players in with Discord and shows their avatar and name. Settings are in dist/chat-config.js: the Discord application's Client ID and the chat server address. The site address must be listed under the Discord application's OAuth2 redirects. Messages go through server/chat-server.js, which has no dependencies: run `DISCORD_CLIENT_ID=<id> node server/chat-server.js` (port 8787; set ALLOWED_ORIGINS to the site address when hosting). The server checks every sender with Discord, keeps the last 50 messages in memory, and is needed because dist/ alone cannot relay messages between players. AI replies are optional: with an Anthropic API key in server/.env (copy server/.env.example; never share .env) and `npm install` run once in server/, server/chat-ai.js has Claude write the characters' answers to real messages through the official SDK. The model is CHAT_AI_MODEL (default claude-opus-5-5), capped by CHAT_AI_PER_MINUTE. Messages the AI is answering are marked `ai:true` so the site skips its scripted reply; if a request fails the server sends `aifail` and the scripted reply steps in. Chat messages and display names go to Anthropic when this is on, which the Privacy Policy states. Tips: signed-in players can send each other play credits from the gift button in chat. A tip needs a 6-digit code that the site's Discord bot sends to the sender by direct message (DISCORD_BOT_TOKEN in server/.env; the bot must share a Discord server with the player). The server holds a confirmed tip until the receiver's browser collects it (`/tips/claim`); held tips are lost if the server restarts. Tips move play credits only: there is no withdraw or cash-out, and none should be added. Balances live in each browser, so the code proves who is tipping, not that they have the credits. Player flips (dist/duels.js, the "Flips" page in the header nav): a signed-in player stakes credits on heads or tails and another joins on the other side (`/flips/create`, `/flips/join`, `/flips/cancel`). The chat server then counts down ten seconds, tosses one fair coin, lets it be seen spinning for six seconds, and only then pays: the winner is owed both stakes with no fee. An unjoined flip is refunded after an hour. A finished flip stays on the Flips list for twenty minutes (`flipKeep`) and is then dropped. Amounts are shown as play credits with the coin icon, never as dollars. Stakes are noted in the profile's `duels` list until the result or refund is collected through `/tips/claim`. The server saves owed credits and open flips in server/data.json. This is the lobby's 14 games plus a separate player-versus-player page, not a fifteenth game card. dist/chat-crowd.js adds simulated chatter from scripted characters and pads the online count; it is worked out in each browser from the clock (ten-minute blocks) and from the real messages, so every viewer sees the same lines at the same time and after a refresh; it is disclosed in the Arcade rules, and is switched off with `crowd:false` in dist/chat-config.js. The characters' profile pictures come from image files the owner puts in dist/art/pfps; run `node server/list-pfps.js` after adding or removing any (it rewrites dist/chat-pfps.js). With no pictures there, drawn ones are used. Game credits and profiles stay in the browser and are not tied to the Discord sign-in.

## Discord bot
server/discord-bot.js is the arcade as a Discord bot, with no dependencies (Node 22 or newer, for the built-in WebSocket): `node server/discord-bot.js` with DISCORD_BOT_TOKEN and DISCORD_CLIENT_ID in server/.env. Only one copy may run: it keeps a lock file (server/bot-data.json.lock) and a second copy refuses to start, because two copies each answer every command and keep separate rounds ("That round has ended"). Optional settings: DISCORD_GUILD_ID registers the slash commands in one server at once (global otherwise), SITE_URL is shown by help, BOT_PREFIX changes the `$`.
Commands are typed with `$` (`$coinflip 50 heads`, `$bj 50`, bets also take `all`, `half`, `1.5k`; words can come in any order) and also exist as slash commands. `$` commands need "Message Content Intent" switched on for the bot in the Developer Portal; without it the bot says so at start-up and carries on with slash commands only. It loads dist/engine.js and dist/floor.js, so its games and odds are the website's: quick games (coinflip, dice, limbo, wheel, war, rps, roulette, plinko), button games (blackjack, mines, tower, hilo: one open round per player, finished for the player after ten idle minutes), flip (a fair player-versus-player coin flip, winner takes both stakes; the message of a flip that was played, cancelled or ran out is deleted twenty minutes later, tracked in `cleanup` in bot-data.json), and balance, refill, tip, profile, leaderboard, ranks, guide, help. `guide` is the how-to-play page (every game and every command, built from the command list so it stays current, plus the bet-size odds); setup posts it in a how-to-play channel. The owner had the separate odds command, the odds channel and the daily claim removed (22 November 2026); do not bring them back unasked. Finished games carry a "Play again" button for the same player.
Pictures: card games send a picture of the table. server/card-images.js cuts cards from one sheet, server/art/cards.png, and writes the PNG itself (no image library); the sheet is drawn from server/art/cards.html by `node server/make-cards.js`, which needs Chrome or another Chromium browser. Other games attach the website's artwork from dist/art. Without the sheet the cards are written as text.
The bet-size odds apply as on the site and are never hidden: each sized command's description points to the guide, the guide's first page states the bet-size tiers, each game message states the chance for the bet, and a bet over 1,500 in a sized game is only taken after a warning and a confirm button. With the odds command gone, those are what keep the odds from being hidden, so keep all of them.
Roles: `$server setup` (or /server setup; server managers only) adds eight roles and four categories of channels to the server it is run in. It reuses anything already there by name and deletes nothing; run again, the only things it edits are its own info pages (brought up to date, matched by embed title) and a channel it made under an earlier name (`was` in the layout, renamed). Ranks (Bronze 1,000 up to Legend 2,000,000) follow a player's total bet and only the highest is kept; High Roller (one bet of 500+) and Whale (1,000+) follow the biggest single bet. No role asks for a bet over 1,500, since that bet cannot win. Roles are synced after each command in servers that have been set up. The bot needs Manage Roles and Manage Channels (the invite link from `inviteLink()` asks for them) and its own role must sit above the roles it hands out.
Bot balances are kept by the bot in server/bot-data.json (keyed by Discord ID; stakes in play are listed under `held` and refunded on the next start; `guilds` holds each server's role IDs) and are separate from the website's browser balances. Credits are free there too (1,000 to start, refill below 10, tip): there is no deposit, purchase, withdraw or cash-out command, and none should be added. `createBot` takes stand-ins for fetch and WebSocket, which is how tests/bot.test.cjs runs it without Discord. The Terms, Privacy and Fair Play pages describe the bot; keep them in step.

## Verify
Run `node --test tests/*.cjs` from this folder. Check an actual round and wallet changes after editing game logic. Keep existing localStorage keys compatible with saved player profiles.

## Hosting
The Discord bot can run on Render from render.yaml (a Blueprint): a background worker, not a web service, with a 1 GB disk at /var/data. DATA_DIR points the bot's bot-data.json at that disk (Render wipes everything else on each restart or deploy) and BOT_LOCK=off skips the one-copy lock there. The bot token is never in the repository: DISCORD_BOT_TOKEN is `sync: false`, so it is typed into Render. Leave Render's Root Directory empty, because the bot reads the game code from dist/. Only one copy of the bot may be connected at a time, so stop the local one when the hosted one is up. The repository is github.com/colzyleader/muck1245u1u89915 (private); pushes to main redeploy.
This is a portable source snapshot. The original site is hosted separately. Player balances and history live in each browser under the original site address. Editing this folder updates the local copy. For a separate host, publish dist/ as a static site and set access for the intended audience.
